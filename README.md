# NotiAI 일정 추출 모델 (slim-v9)

> 다중 프롬프트 기반 AI 대학생 일정 자동 생성 시스템 · 충북대학교 소프트웨어학부 졸업작품

NotiAI는 학교 공지, 공모전, 대외활동 공지를 자동으로 모아서 **학생이 직접 챙겨야 하는 일정**만 뽑아 보여 주는 서비스입니다. 이 저장소는 그 중심인 **일정 추출 모델**입니다. 공지 한 건(제목·본문·게시일)을 넣으면 신청 마감, 제출 마감, 참석 행사, 면접 같은 일정 목록을 JSON으로 돌려줍니다.

- 백엔드: [capstonenotiai/backend](https://github.com/capstonenotiai/backend) · 프론트엔드: [capstonenotiai/frontend](https://github.com/capstonenotiai/frontend)
- 현재 서비스 모델: **slim-v9** (Llama-3.1-8B-Instruct + LoRA)

Built with Llama

## 서비스에서 하는 일

```
[수집] 충북대 공지 · 콘테스트코리아 · 위비티
   ↓ 공지 원문 (제목, 본문, 게시일)
[일정 추출 모델 · 이 저장소]  공지 1건 → 일정 목록 JSON
   ↓
[백엔드]  저장 · 사이트 마감일과 대조 · "확인 필요" 표시
   ↓
[웹]  일정 목록 · 상세 화면 · Google Calendar 등록 · 마감 알림 · AI 플래너 추천
```

- **일정 목록**: 공지마다 대표 일정 1개(아직 마감되지 않은 가장 가까운 접수 마감, 접수가 없으면 본행사)를 D-day와 함께 보여 줍니다. 모든 접수가 끝난 공지는 목록에서 빠집니다.
- **상세 화면**: 그 공지에서 뽑은 모든 일정과 원문 링크를 보여 줍니다. 사용자는 일정을 직접 고칠 수 있습니다.
- **캘린더 등록**: "일정 등록"을 누르면 그 공지의 일정을 Google Calendar에 함께 넣습니다. 서류 합격자만 해당하는 **면접은 자동 등록하지 않습니다**. 그래서 모델은 면접을 `interview`로 따로 구분합니다.
- **확인 필요**: 모델이 검토가 필요하다고 표시했거나 사이트가 적은 접수 마감일과 모델 결과가 다르면, 사용자에게 공지에서 날짜를 한 번 확인해 달라고 안내합니다.
- **알림**: 마감 D-3·D-1 오전 9시에 이메일과 서비스 알림함으로 알려 줍니다.

모델은 일정을 **빠짐없이, 그리고 없는 일정은 만들지 않게** 뽑는 데 집중합니다. 무엇을 화면에 보여 줄지는 서비스가 정합니다.

## 무엇을 일정으로 뽑나

학생이 **직접 행동해야 하는 날짜**만 일정입니다.

| 뽑는 것 | 뽑지 않는 것 |
|---|---|
| 신청·지원·접수 마감 (`application`) | 결과·서류·합격·수상 발표 |
| 제출·응모 마감, 등록금·참가비 납부 마감 (`submission`) | 시상이 포함된 행사, 시상품 수령 |
| 설명회·특강·발대식·OT·필수 사전교육·수료식 (`event`) | 몇 달짜리 활동·교육·운영 기간 |
| 날짜가 적힌 면접 (`interview`) | 선택 참여 설문, 시스템 점검·시설 이용 안내 |

- 접수와 본행사가 따로 적혀 있으면 나눠서 뽑습니다. 공지에 없는 단계는 만들지 않습니다.
- 접수 일정의 장소는 방문·현장 접수처가 적힌 경우에만 넣습니다. 시각은 그 일정에 적힌 경우에만 넣습니다.
- 연도가 없는 날짜는 게시일 이후 12개월 안에서 그 날짜가 처음 오는 해로 정합니다. 게시일이 없으면 연도를 추정하지 않습니다.
- 요일과 날짜가 다르면 숫자 날짜를, 사이트 요약과 본문이 다르면 본문을 따릅니다.

### 예시

입력

```json
{
  "title": "2026 학생 아이디어 공모전 참가자 모집",
  "body": "접수기간: 2026년 11월 3일(월) ~ 11월 14일(금) 18:00까지\n제출방법: 이메일 제출\n결과발표: 11월 28일\n시상식: 12월 5일 14:00 본관 대회의실",
  "reference_time": "2026-10-19"
}
```

출력 (일정 부분)

```json
{"events": [{
  "event_type": "application",
  "title": "2026 학생 아이디어 공모전 참가자",
  "start_date": "2026-11-03", "end_date": "2026-11-14",
  "start_time": null, "end_time": "18:00",
  "location": null, "attendance_mode": "not_applicable"
}]}
```

결과 발표와 시상식은 정책대로 빠집니다.

## 모델

| 항목 | 내용 |
|---|---|
| 기반 모델 | Llama-3.1-8B-Instruct, 4bit QLoRA |
| 출력 | 공지 1건 → 일정 여러 개, 일정마다 8개 필드(유형, 제목, 시작·종료 날짜, 시작·종료 시각, 장소, 참여 방식) |
| 학습 | 7월 단일 일정 모델(v10)의 LoRA에서 이어 학습, 3 epoch, 최대 4,096토큰 |
| 학습 데이터 | 실제 공지 약 800건(충북대 공지, 대외활동·공모전), 일정 없는 공지 포함. 정답은 위 정책으로 사람이 검토 |
| 서버 후처리 | 잘못된 달력 날짜·역전 기간 정리, 날짜 없는 일정 제거, 온라인 일정의 장소 정리 |
| 실행 | GPU 1장(RTX 5070 Ti 16GB에서 공지당 평균 약 7초) |

### 개발 과정

- **7월 (v10)**: 공지 하나에서 일정 하나만 뽑는 5필드 모델. 여러 일정이 있는 공지와 면접·발대식 같은 단계를 표현하지 못했습니다.
- **10월 (slim 계열)**: 일정 여러 개와 유형을 뽑는 형식으로 바꾸고, 일정 정책을 정한 뒤 학습 데이터를 다시 정리했습니다. 일정 없는 공지를 넣어 없는 일정을 만들어 내는 문제를 줄이고(v8), 대외활동 공지를 보강해 v9를 서비스 모델로 정했습니다.
- **v9b (미채택)**: 실제 서비스에서 모은 공지로 데이터를 보강했지만, 미리 정한 채택 기준(정밀도 하락 3%p 이내 등)을 넘지 못해 v9를 유지했습니다.

## 성능

**독립 평가셋**: 모델 개발에 쓰지 않은 실제 수집 공지 56건입니다. 두 명이 서로 모르게 정답을 작성한 뒤 차이를 판정했고, 판정할 수 없는 7건을 빼고 49건을 채점했습니다. 서비스에서 실제로 쓰는 후처리 후 결과입니다.

| 지표 | 결과 |
|---|---:|
| 공지 완벽 일치 (공지의 모든 일정이 정답과 같음) | 73.5% (36/49) |
| 일정 재현율 / 정밀도 | 84.1% / 100.0% |
| 날짜 / 접수 마감일 정확도 | 94.3% / 93.3% |
| 장소 / 시각 정확도 | 96.2% / 89.5% |
| 원문에 없는 날짜 · 일정 없는 공지에 일정 생성 · 무효 응답 | 0 / 0 / 0 |

공지 수가 적어 공지 1건이 약 2%p입니다.

**개발 평가셋** (135건, 모델 개선 과정에서 반복 사용):

| 지표 | 원시 출력 | 후처리 후 |
|---|---:|---:|
| 공지 완벽 일치 | 68.9% | 71.1% |
| 일정 재현율 / 정밀도 | 87.7% / 93.4% | 87.7% / 95.5% |
| 날짜 / 접수 마감일 정확도 | 90.1% / 93.2% | 90.1% / 93.2% |
| 원문에 없는 날짜 / 일정 없는 공지 오류 | 0.7% / 4.2% | 0.7% / 0.0% |

응답 시간은 평균 6.6초, p95 16.5초였고 생성 완료율은 100%입니다. 7월에 만든 봉인 테스트(단일 일정 175건)의 날짜+장소 정확도는 73.7%입니다.

### 평가 방법

- 정답은 모델 출력을 보지 않고 원문만 읽어 작성했습니다.
- 채점 규칙과 채택 기준은 모델을 돌리기 전에 문서로 고정했고, 결과를 본 뒤 바꾸지 않았습니다. 근소하게 미달한 후보도 채택하지 않았습니다.
- 평가 공지와 겹치는 공지(같은 URL, 같은 제목, 본문 대부분 일치)는 학습 데이터에서 뺐습니다.

## 실행

Python 3.11과 CUDA GPU가 필요합니다. 기반 모델과 LoRA 가중치는 이 저장소에 없습니다. 기반 모델은 Meta 이용 조건에 동의하고 로컬에 준비합니다.

```powershell
python -m pip install -r requirements.txt
python -m model_server.slim_server --prompt-mode slim-v9 --interview-type passthrough --model-dir <adapter 폴더> --host 127.0.0.1 --port 8765
```

```powershell
# 요청 예시
curl -X POST http://127.0.0.1:8765/extract -H "Content-Type: application/json" -d '{"title":"...","body":"...","reference_time":"2026-10-19"}'
```

- 다른 PC에서 접속하게 하려면 `--host 0.0.0.0`과 함께 `MODEL_API_TOKEN` 환경변수(32자 이상)를 설정합니다. 그러면 모든 요청에 `X-Model-Token` 헤더가 필요합니다.
- 요청·응답 형식, 오류 코드, 메타데이터: [docs/API.md](docs/API.md)
- 이어서 학습하는 방법: [docs/TRAINING.md](docs/TRAINING.md)

```powershell
python -B -m unittest discover -s tests -v   # 가중치 없이 도는 테스트
python -B tools/check_release.py             # 가중치·데이터·비밀값이 섞이지 않았는지 점검
```

## 저장소 구성

| 경로 | 내용 |
|---|---|
| `model_server/` | 추출 서버(`slim_server.py`), 모델 실행·후처리(`slim_v1.py`, `runtime.py`), 프롬프트(`prompts/`, `prompt_input.py`), 출력 검증(`validation.py`) |
| `training/` | LoRA 이어 학습 코드 |
| `tests/` | 후처리·API 계약·HTTP 테스트 |
| `tools/check_release.py` | 공개 전 점검 |
| `docs/` | API, 학습 문서 |

학습 데이터, 평가 정답, 수집한 공지 원문, 가중치는 공개하지 않습니다.

## 한계

- 일정 누락, 불필요한 일정, 장소 연결 오류, 연도 해석 오류가 남아 있습니다. 그래서 서비스는 원문 링크와 함께 보여 주고 사용자가 고칠 수 있게 합니다.
- 첨부파일(PDF, 이미지)에만 있는 일정은 읽지 않습니다.
- 평가셋이 수십~백여 건이라 몇 %p 차이는 오차 범위 안입니다.
